# Доказательства и источники

## Исторические результаты

`history/` содержит отчёты выполненной исследовательской сессии. Их метрики относятся к разным контурам:

- `*-report.json` классических моделей, `template-text-v2-report.json`, `sequence-full-report.json` — development 5-fold CV на фиксированной группировке.
- `confirmation-decision.json` — историческая проверка заранее выбранной смеси на confirmation.
- `encoder-pilot-report.json` — последний отрицательный эксперимент на одном фолде, не full CV.
- `official-submission-10588.json` — сохранённое чтение результата и строки рейтинга после официальной отправки. Это не свежая проверка рейтинга.
- `representation-audit-v2.md` — особенности исходных диалогов и причины выбора единицы группировки.
- `competition-rules.txt` — сохранённый текст правил; актуальные правила следует проверять на сайте организатора.

`session-facts.json` содержит заново пересчитанные агрегаты официальных данных, значения исторических метрик и SHA-256 источников. Суммы классов, типов диалогов, бинов длины и split membership программно сверены с числом объектов.

## Новый проверочный запуск

Новый запуск baseline не подменяет исторические эксперименты. Его реальный трекер создаётся непосредственно при выполнении `../run.sh`: параметры, effective model defaults, метрики, исходники, данные и артефакты получают собственную привязку к run ID.

`reproduction-proof.json`, если присутствует, — отдельный результат проверки переносимого пакета. Он должен содержать фактический run ID, метрики, число OOF/TEST-строк и результаты чтения трекера. Отсутствие такого файла означает, что доказательство запуска ещё не приложено; исторические отчёты сами по себе его не заменяют.

Сырые данные, скрытые test labels, pretrained-веса, аккаунты и секреты в этой папке не хранятся. Контрольные суммы публичных файлов модели — не API-ключи; исключения secret scanner ограничены точными строками с конкретными публичными SHA-256.
